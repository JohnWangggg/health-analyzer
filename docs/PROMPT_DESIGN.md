# 提示词设计说明

**语言 / Language：** **中文** | [English](./en/PROMPT_DESIGN.md)

## 设计目标

让用户**一键复制一段文本**，粘贴到大模型平台后，能稳定生成符合既有报告格式的深度分析报告，无需反复调试提示词。

## 提示词结构

主提示词模板 `MAIN_PROMPT_TEMPLATE` 包含 5 层：

### 第 1 层：角色与任务（Role & Task）
明确 LLM 身份："严谨的临床数据分析师"，定义 4 条行为边界。

### 第 2 层：输出结构（Structure）
定义固定标题结构：
- 总结判断
- 各数据维度章节（CGM / 血压 / 体重 / HRV / 心率 / 步数 / 睡眠 / ECG）
- 监测仪表盘
- 需要复查或升级处理的信号
- 当前工作假设
- 参考依据；无数据的维度跳过

### 第 3 层：风格要求（Style）
- 中文 / Markdown 表格 / 数字右对齐
- 关键发现加粗
- 区分"已确认"vs"待验证"vs"假设"
- 异常 CGM 必须给"指尖血复核"建议

### 第 4 层：边界声明（Disclaimer）
- CGM 组织间液滞后说明
- 不替代门诊
- 降压/降糖方案调整请遵医嘱

### 第 5 层：原始数据（Data）
动态填充用户的实际统计结果。

## 三档提示词的差异

| 标签 | 用途 | 适合场景 |
|---|---|---|
| 完整提示词 | 直接粘贴到对话框，按固定标题结构生成报告（无数据维度跳过） | 想要标准输出 |
| 仅数据摘要 | 自己写 system prompt，仅提供数据 | 想自定义引导风格 |
| 简短系统提示词 | 粘贴到 system 字段，再粘数据 | 平台有独立 system / user 字段 |

## 关键设计原则

### 1. 数据边界声明放在指令前

大模型倾向于"基于数据给结论"，但健康数据不应过度推断。在提示词开头就声明"不下诊断结论"，比放在结尾更有效。

### 2. 阈值硬编码

不在提示词中写"血糖偏低如何如何"，而是写：
- "CGM <3.9 必须建议指尖血复核"
- "<3.0 升级为按低血糖处理"
- "随机 >11.1 或空腹 >7.0 为高血糖"

让 LLM 把数字与阈值匹配即可，避免 LLM 自由发挥医学建议。

### 3. 章节标签动态调整

主提示词使用固定标题而不是 `N+1` 形式，LLM 会根据 `dataAvailability` 中的字段决定是否输出对应维度。如果用户没有血压数据，LLM 会跳过血压章节，避免章节编号混乱。

### 4. 提示词长度控制

明细表默认只展示各数据维度最近 90 天，更早数据保留在总体统计中。完整提示词的长度取决于实际数据量，通常明显低于逐条输出全部历史记录。适合：
- 豆包 / Kimi：128K 上下文
- ChatGPT-4：8K-128K（视版本）
- Claude 3.5：200K
- Gemini 1.5 Pro：1M-2M

## 调优建议

如果发现 LLM 输出不符合预期，可调整：

1. **想要更详细的解读**：在 `## 写作风格要求` 后加 "请给出每个数字背后的临床/生理学解释"
2. **想要更简洁的表格**：加 "表格只保留关键列，不超过 5 列"
3. **想要英文输出**：替换 `中文输出` 为 `English output`
4. **想要特定医生视角**：修改 `角色与任务` 为 "你是一位心血管内科主任医师"
5. **不想要免责声明**：删除 `# 数据使用边界声明` 段落（不推荐）

## 复用性

主提示词可独立使用——即使不通过本应用，您也可以：
- 把数据按 `formatAnalysisForLLM()` 输出的格式整理好
- 拼接 `MAIN_PROMPT_TEMPLATE`
- 粘贴到任何 LLM

这意味着此提示词也是一份**可单独发布的开源资产**。
